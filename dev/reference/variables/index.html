    Reference: environment and configuration¶

    TandemEngine reads four families of settings. Engine switches are QWEN38_* variables, read through one registry. Server settings are command-line flags (Command-line reference); ops/start.sh builds them from ops/serve.env, and a few QSE_* variables set flags' defaults or serve the scripts. The installer and the service scripts read a few TANDEM_* variables. And the conductor's behaviour lives in its versioned documents, which the dashboard edits. The QWEN38_* knobs the extension reads, and the variables of TandemApp's proxy, collector and plugins, are in TandemApp's docs.

    The served profile¶

    ops/serve.env is the served configuration. On an installed engine it is ~/TandemLLM/run/ops/serve.env, rewritten by every run of the installer, and local.env beside it is read last for your own values.

    The most used: QSE_CONDUCTOR_CONFIG, QSE_USAGE_LEDGER, QSE_DISK_CACHE and QSE_BACKENDS name the conductor's directory, the ledger, the disk tier's directory and the proxy's config database; ops/start.sh passes them to the service only, so a benchmark server started with serve.env exported never writes them. QSE_DASHBOARD_LOGIN turns the dashboard login on. QSE_ADMIN_TOKEN and QSE_METRICS_TOKEN live in secrets.env, which ops/make-secrets.sh writes.

    The wait for memory (Waiting for memory) reads these, with their code defaults: QSE_MEM_WAIT_S (10,800) is the longest wait in seconds of a streamed request, or of one that sends wait_for_memory: true; QSE_PARALLEL_FLOOR_GB (15) is the floor the admission keeps MemAvailable at, the same as --parallel-floor-gb; QSE_KV_HARD_FLOOR_GB (10) is the floor the KV pool's commits keep, the same as --kv-hard-floor-gb; QSE_GUARD_MARGIN_GB (5) is the margin each floor holds under the largest step the engine takes between two checks; QSE_KV_ADMIT_ROWS (8,192) is the part of max_tokens the admission reserves KV pages for, 0 for all of it; QSE_KV_RECOMPUTE (on) lets a lane the pool refuses give way and go on later; QSE_PEAK_STRICT (0) set to 1 makes a lone request that the memory gate refuses wait too.

    The conductor's versioned documents.

    A document is JSON, checked against the conductor's schema (GET /v1/conductor/meta serves it, and TandemApp's contracts/conductor-v1/ holds a copy). A version stored by an older release loads with defaults for every field it lacks, and the journal says so once.
